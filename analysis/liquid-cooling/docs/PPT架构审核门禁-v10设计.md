# 海悟液冷PPT架构审核门禁（Gate Review Process）

> 🔴 P0 强制性前置审批 | 2026-05-09 确立
> 规则：AI 生成完整PPT前必须先提交架构设计，用户审核通过后方可执行。

---

## 一、门禁触发条件

以下任一情况触发架构审核：

| 触发条件 | 示例 |
|---------|------|
| 新建PPT | 首次构建液冷洞察PPT |
| 架构变更 | 章节重组、视角切换（如v9重构：四部分→五看三定） |
| 数据重大更新 | 季度财报批量刷新、GPU路线图更新 |
| 新增分析维度 | 如新增运维市场分析、海外收入线 |
| 用户主动要求 | "重新设计架构"、"换个结构" |

**不触发的情况**：单页数据修正、备注补充、格式调整等不影响结构的变更。

---

## 二、架构设计文档模板

AI 提交审核时，必须包含以下内容：

```markdown
# PPT架构设计 — [标题] v[X]

## 1. 目标读者
- 谁看这份PPT？（海悟高管/投资方/客户/内部）
- 他们关心什么？（战略方向/市场空间/行动路线）

## 2. 核心叙事线
- 一句话概括：这份PPT回答什么问题？
- 叙事逻辑：从____到____再到____（3段论）

## 3. 章节结构
| 章节 | 标题 | 页数 | 核心内容 | 数据来源 |
|------|------|------|---------|---------|

## 4. 方法论声明
- 分析框架（五看三定/四维度/其他）
- 数据口径（全球/中国/机柜级/全品类）
- 价格基准（全球基准USD/国产化¥）

## 5. 关键假设
- 列出所有需要显式声明的前提假设

## 6. 数据溯源检查
- 每页数据是否能追溯到源文件？
- 是否有过期数据混入？
- 铁律⑤是否生效（最新源文件为准）？
```

---

## 三、审核流程

```
AI 完成架构设计
    │
    ▼
提交架构文档 → 等待用户审核
    │
    ├── ✅ 通过 → 执行PPT生成
    ├── 🔄 修改 → AI调整架构后重新提交
    └── ❌ 否决 → 放弃，回到brainstorming
```

**用户审核要点**：
1. 章节结构是否合理
2. 核心结论方向是否正确
3. 数据口径是否有误
4. 关键假设是否接受
